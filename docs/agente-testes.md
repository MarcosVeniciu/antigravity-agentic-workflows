# Tests Agent (`/testes`) - The Red Phase

The Tests Agent is the starting point of the development cycle after the architecture has been approved. Strictly following the TDD (Test-Driven Development) philosophy, it acts in the **Red Phase**, that is, it creates the tests before any line of production logic exists.

---

## 1. The Agent's Focus

The central goal of this agent is to create a protective mesh for the next step (coding). It takes the technical document (SDD) generated by the Artifacts agent — which has already defined classes, methods, and contracts — and transforms it into executable assertions.

### AAA Pattern (Arrange-Act-Assert)
All tests generated by this agent strictly follow the AAA pattern:
1. **Arrange:** Configuration of the initial state, mocks, and fixtures.
2. **Act:** Execution of the target function or method.
3. **Assert:** Validation of results and expected state changes.

### Comprehensive Coverage
The generated test suite is divided into fundamental pillars:
* **Happy Path:** The main success scenario based on the original BDD contract.
* **Edge Cases:** Limiting cases and boundary behaviors.
* **Exceptions:** Rigorous validation that the code fails with expected exceptions when subjected to invalid inputs or scenarios.
* **Performance / Native Profiling:** Tests focused on measuring response times (Time vs Inputs N), preparing the ground for asymptotic complexity analysis (Big-O).

---

## 2. Cognitive Restriction

**Forbidden to generate production code:** The Tests Agent is absolutely forbidden to implement business logic. It *pretends* the code already exists (using the definitions mapped in the artifacts phase) and tests only the interface and contracts.

---

## 3. The Context in the TDD Flow

This agent does not act in isolation. The development flow heavily depends on what it produces:
1. It receives the contracts from the **Artifacts Agent** (`/artefatos`).
2. Once the test suite (which will initially fail, Red Phase) is created, it passes the baton to the **Code Agent** (`/codigo`), whose exclusive mission will be to make that suite pass (Green Phase).

Having an agent that focuses 100% only on structuring tests prevents the model from trying to write the validation and the implementation simultaneously, which would frequently result in biased tests (tests created just to pass on the specific logic that the AI just came up with).
