### 📥 Example User Question
> "How does test coverage validation work in the CI pipeline and which file manages it?"

### 📤 Example Agent Response (Project Oracle)

Based on the analysis of the repository and Obsidian knowledge base, here are the details regarding test coverage validation:

#### 1. Business Rule and Governance
Coverage validation was established to ensure that no code changes reduce the global test index below the minimum target set by the engineering team.
* Global coverage target is set at **90%**.
* If coverage falls below this threshold, the script halts execution returning a failure code (`sys.exit(1)`), preventing pipeline progression.

This guideline is documented in the project core conventions note: `[[conventions]]`.

#### 2. Technical Implementation
Verification logic is automatically executed by a Python utility script. It reads a JSON file generated by the coverage tool and analyzes total fields.

Corresponding code is implemented in the engineering agent skills folder:
* Verification file: [`verify_coverage.py`](file:///project/skills/codigo/scripts/verify_coverage.py#L70-L80)
