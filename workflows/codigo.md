### 2. Implementation Protocol

#### 2.1. Code-to-Test Alignment

* Write production code that directly satisfies each test's assertion. Do not add functionality beyond what the tests require.
* If a test expects a specific exception, implement the exact exception class and raise condition.
* If a test mocks a dependency interface, implement that interface exactly as mocked (same method signatures, same return types).

#### 2.2. Structural Quality

* **Single Responsibility:** Each function/method should do one thing well. If a function grows beyond ~20 lines, consider whether it's handling multiple concerns.
* **Explicit over Implicit:** Favor explicit type hints, explicit return statements, and explicit error handling over magic or convention.
* **No Dead Code (Current Scope):** Do not leave commented-out code, unused imports, or placeholder implementations (`pass`) for the logic you are tasked to write.
* **Standardized Tags (Future Tech Debt):** When indicating future improvements, known limitations, or technical debt outside the immediate scope, use standard developer tags. 
  - Supported tags include: `TODO`, `FIXME`, `HACK`, `OPTIMIZE`, `BUG`, `REFACTOR`, `NOTE`.
  - *Examples:* 
    - `# TODO: Add caching layer to this query in the next sprint.`
    - `# FIXME: Edge case fails if user age is negative.`

    - **Purpose:** A concise summary of what the code does.
    - **Arguments/Parameters:** Names, expected data types, and descriptions.
    - **Returns:** Expected output data type and description.
    - **Raises:** Any specific exceptions or errors intentionally thrown.
    - **Domain & Architecture Context:** A brief note linking the function to the specific business rule it resolves. **CRITICAL:** When referencing Obsidian notes (`obsidian_knowledge_graph`), you MUST strictly use the exact format: `Ref: Obsidian note [[note-name]]`. * **Inline Narrative:** Precede complex logical blocks with comments explaining the *intent* and *why* (the business reason), avoiding redundant descriptions of standard syntax.
